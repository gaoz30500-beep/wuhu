# 做题复习

面向技术学习的分批刷题与错题闭环复习。核心目标是：**少量多批、边做边改、错题吃透、延伸拔高**。

## 触发场景
- 用户在学某个知识点（如 MySQL、存储引擎、索引、编程语言等），想通过做题巩固检验。
- 用户需批改已做题目、汇总错题、重写错题、做变题或企业级面试题。
- 用户说"出题 / 给题 / 继续 / 下一套 / 下一类 / 错题发我 / 这题不会"。

## 核心流程（严格按顺序执行）

### 第1步：按题型分批出题
- 出题顺序固定：**选择题 → 判断题 → 填空题 → 实操题**。
- **一次只发一种题型**，控制题量"一点点来、合理分配"，不一次性灌满。
- 在用户完成并确认当前题型前，不发下一种题型；用户问"把没做的题发我"时才补发剩余题型。

### 第2步：收答案 + 批改
- 用户可只提交某一类题型的答案，边做边改。
- 逐题核对，标注 ✅正确 / ❌错误；`?>B` 表示该题/该空不会，单独标记为"不会"。
- 批改要简洁清晰，推荐用表格列出：题号、你的答案、正确答案、是否正确、一句话要点。

### 第3步：错题详细讲解 + 延伸拓展
对每个错题 / 不会的题：
- **正确原理**：讲清知识点本身。
- **为什么错**：指出错误点与常见误区。
- **易错坑点 + 记忆口诀**：给出好记的口诀或对比。
- **延伸拓展**：相关概念、对比、边界情况、常见面试问法，帮用户举一反三，不只停在题目本身。
- 对题目涉及的邻近知识点做适度展开，串成知识脉络。

### 第4步：错题重写（一轮巩固）
- 全部题型做完后，**汇总输出全部错题原题（含标记不会的题）**，让用户重新作答。
- 用户重写后再批改一次；仍未掌握的继续讲解，直到吃透。

### 第5步：变题强化（二轮巩固）
- 针对错题出**变题**：改数字、改问法、换情境、反着问。
- 让用户再做，检验是否真正理解而非背答案。

### 第6步：企业级思考题 / 面试题（拔高）
- 用户确认已掌握后，再提供**企业级思考题 / 面试真题**（结合真实业务场景）。
- 这类题要有深度：问原理、问取舍、问场景应用、问底层机制。

## 交互节奏规则
- 出题和批改都以"少量多次"为原则，避免一次性信息过载。
- 用户随时可打断提问：**先回答提问，再继续刷题流程**。
- 不提前一次性发放整套题，防止用户记答案。
- 全程使用用户所用语言。

## 出题内容质量要求
- 题目围绕用户正在学的知识点/教材/章节展开，难度循序渐进。
- 覆盖基础概念、易混对比、陷阱细节、实际应用。
- 企业面试题需贴合真实业务场景，考察理解深度而非记忆。

## 执行参考示例（以 MySQL 存储引擎为例）
1. 发"第1套 · 选择题"5题 → 收答案批改 → 讲解错题+延伸。
2. 再发"判断题" → 批改讲解。
3. 再发"填空题" → 批改讲解。
4. 再发"实操题" → 批改讲解。
5. 汇总错题原题，让用户重写 → 批改。
6. 出变题强化 → 批改。
7. 用户确认掌握后，出企业级思考题 / 面试题。
